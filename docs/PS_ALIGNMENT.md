## What "isosurface" means here, precisely

True volumetric marching cubes needs a mesher we can't visually verify
without a browser in this environment. Instead, `backend/contouring.py`
implements marching **squares** — the standard, well-defined 2D case of the
same algorithm — per depth layer, and the frontend stacks each layer's
contour lines at their real depth. This is a genuine, tested numerical
technique (unit-verified against a synthetic radial field and a two-peak
field during development; see the module's docstring) and matches how
oceanographic tools like Ocean Data View actually render "isosurfaces" in
practice: as stacked isolines. It is not full mesh-based volume rendering,
and this document says so rather than overselling it.

## What's genuinely synthetic

Every number in the shipped dataset is generated by `DemoAdapter` — no
placeholder pretending to be real INCOIS/Argo/Copernicus data. The network
sandbox this was built in can't reach `ftp.ifremer.fr`, `las.incois.gov.in`,
or Copernicus Marine, so real ingestion is wired and documented
(`data/README_DATA.md`, `scripts/fetch_argo_data.py`) rather than faked.
